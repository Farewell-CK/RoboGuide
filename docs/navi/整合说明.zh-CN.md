# NAVI 室内导航接入 RoboGuide

本次以 `feat/navigation-data-archive` 的 `88a1f0893578dca3414e54490da1b3b8dfebc152` 为基线，将已经实测的 NAVI 1.0.14 室内导航作为 Flutter 模块嵌入 Android 宿主。入口位于 RoboGuide 的“导航”页 →“NAVI 室内导航”，功能运行在同一个应用包内，不启动外部 NAVI 应用。

## 源码位置

| 位置 | 内容 |
|---|---|
| `navi_indoor/lib` | 中文地图管理、路线录制、定位、路线跟踪、方向校准、到达、语音与字幕 |
| `navi_indoor/test` | 原有 68 项回归测试 |
| `navi_indoor/database_scheme.sql` | 上游数据库结构参考 |
| `app/src/main/java/com/seaway/guideassistant/navindoor` | Flutter 页面宿主、计步传感器、图像压缩及入口互斥判断 |
| `services/navi_vision` | 已部署的 DINOv2 CPU 网关快照、GPU 包装层和依赖锁定清单 |
| `tools/build_navi_indoor.sh` / `.ps1` | 模块分析、测试和 AAR 构建 |

源码源自 `NgWY02/Indoor-Navigation-for-visually-impaired` 的 `5b734064622c9a9f2537af451aabfe9d3b469a41`，在本项目实地调试中修改。历史上游介绍见 `UPSTREAM_README.md`，其中的性能和完整功能描述不代表本次整合的实测结论。模型权重、已录制地图、用户登录信息、密钥和本地工具链不随源码提交。

## 构建

需要 JDK 17、Flutter 3.35.7、Android SDK 36，以及原项目所需的 NDK、CMake 和 LFS 原生资源。Flutter 模块与原生宿主各自使用其工具链，通过本地 Maven AAR 连接。

宿主 AGP 统一为 8.9.1、Kotlin 为 2.1.0，`robonix` 切换到相同版本的 Compose 编译插件，兼容 Flutter 插件带入的 AndroidX/Kotlin 依赖。

```bash
git lfs pull
bash tools/build_navi_indoor.sh
./gradlew :app:testDebugUnitTest :navoutdoor:testSwinlDebugUnitTest :app:verifyNaviDebugApk \
  -PswinlFast=true -ParchiveTest=true -PnaviIntegrationTest=true --no-daemon
```

Windows 可先运行 `powershell -File tools/build_navi_indoor.ps1`，再运行 `gradlew.bat`。中国网络环境可设置 `FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn` 和 `PUB_HOSTED_URL=https://pub.flutter-io.cn`。打包后校验 Flutter 引擎、Dart 代码和空白 `.env` 资产，避免宿主默认忽略点文件而导致启动失败。生成的 `.android`、AAR、SDK 路径及构建输出不提交。

如 Google Maven 不可访问，额外设置 `NAVI_MAVEN_MIRROR=aliyun`；准备脚本只修改模块自动打包后校验 Flutter 引擎、Dart 代码和空白 `.env` 资产，避免宿主默认忽略点文件而导致启动失败。生成的 `.android` 仓库，不修改 Flutter SDK 或全局缓存。模型下载可用 `python tools/fetch_navigation_assets.py` 仅拉取快速构建所需的 5 个 LFS 资源，并校验大小和 SHA-256。服务源码与原测试服务器脚本的适用条件见 `services/navi_vision/README.md`。

准备脚本会跳过 Flutter 依赖插件的联网 Javadoc 生成，解决 `jni_flutter` 在 AGP 8.9.1 下的文档生成失败；不跳过插件运行代码或源代码 AAR。

## 手机使用

1. 打开整合测试包，进入“导航”，点击“NAVI 室内导航”。现有导航或归档任务进行中时先结束该任务，避免两套相机、计步与语音同时工作。
   RoboGuide 自身仍保留原分支的本地模拟登录页，与后续 NAVI 的 Supabase 真实登录不同；本次没有将两套账号合并。
2. 首次进入填写视觉服务地址、Supabase 项目地址和公开客户端 key；使用原 NAVI 的数据库账号登录，可以读取同一后台的地图和路线。新应用包不会自动继承独立 NAVI 的登录状态和本机诊断文件。
   邮箱确认和密码找回沿用原有认证回调；若与独立 NAVI 同时安装，系统询问打开应用时选择“RoboGuide·NAVI”。
3. 依次验证地图加载、定位、方向校准、路线推进、拐角确认和到达；确认中文字幕、媒体音量及“重播提示”。按系统返回键退出 NAVI，可回到宿主导航页。
4. GPU 服务仍部署于服务器。手机使用流量时继续保持 Tailscale 连接；同一 APK 整合不会改变移动网络直连/中继状态，也不会把 GPU 推理搬进手机。

## 整合边界

- 地图和路线仍由 NAVI/Supabase 管理；RoboGuide 的账号、机器狗、眼镜和原生导航功能保留。
- 两种导航目前通过用户选择入口切换，不自动衔接机器狗的室内阶段或室外到室内的任务交接。
- 原分支的 RGB-D、Swin-L、OctoMap 完整档案属于原生导航采集链。NAVI 本机定位/匹配诊断仍由原来的诊断页查看，本次不把它冒充为已接入原生完整数据归档。
- `-PnaviIntegrationTest=true` 生成 `com.seaway.guideassistant.swinl.navi`，名称为“RoboGuide·NAVI”，可与旧 NAVI 和原生归档测试包并存。签名或包名不同不能覆盖旧 NAVI。请保留旧包进行对照，不以卸载清空数据作为迁移办法。

## 本次验证（2026-11-10）

- NAVI Flutter：68 项测试通过，分析没有阻断错误；历史警告及提示尚未全部清理。
- RoboGuide 原生导航：258 项测试通过；新增入口互斥测试 1 项通过，合计 327 项。
- Flutter ARM64 release AAR、宿主 Debug APK 构建与最终内容校验通过。
- APK 签名校验通过，下载后 SHA-256 与服务器一致；详见 `validation.json`。
- 安装包约 611 MiB，包含原项目的 Swin-L 模型及原生库，因此明显大于独立 NAVI。

尚未在手机上验证整合包的页面往返、相机恢复、语音播放及完整路线；原生硬件链路也没有重新进行眼镜/机器狗实测。源码和 APK 的构建通过，不等同于整合后的实地导航验证通过。
