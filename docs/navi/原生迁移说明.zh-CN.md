# NAVI 原生 Android 迁移（2026-11-20）

当前原生版集成到 `feat/guide-assistant`。2026-11-23 将原生迁移从 `feat/navigation-data-archive` 调整至此分支，同时保留该分支已有的 D455 与导航录制修复；原分支通过回退提交撤销此次原生迁移。

## 调整原因

旧方案通过 Flutter add-to-app 将独立 NAVI 嵌入 RoboGuide，需要先生成 Flutter AAR，再构建宿主 APK。该方式增加 Flutter SDK、Dart 依赖、插件与独立构建产物的维护。本分支改用同一 Android 工具链编译的 Kotlin library 模块 naviindoor，保留原入口 Activity 类名和包名。

## 功能对应

| 功能 | 原生实现与兼容方式 |
|---|---|
| 连接与账号 | 沿用两个服务地址和公开客户端 key；Supabase 登录、普通用户注册、密码恢复、会话刷新；令牌使用 Android Keystore 加密 |
| 管理员 | 读取 profiles.role 与 organization_id；已有管理员保留角色；新用户注册后由已有管理员授权，不把客户端注册码当权限凭据 |
| 地图与点位 | 兼容 maps、map_nodes、base64 地图与 Storage 图片；地图上点选新地点，照片或环视视频采集定位参考 |
| 路线录制 | CameraX 每约2.5秒采集原始画面，保存当时罗盘朝向；支持暂停、直行/左转/右转补拍、终点补拍与本地草稿 |
| 上传恢复 | 特征提取结果逐点缓存，原始画面留在应用私有目录；稳定 path/waypoint ID、分批 upsert，上传后检查连续序号 |
| 初始定位 | 768维 DINOv2 余弦相似度，门槛严格大于0.5；同地点多视角去重，显示前三候选与参考图片 |
| 路线跟踪 | 普通点0.7，转弯/转弯前/终点0.8；直行窗口最多前看2点，不跨关键点；起始/关键点2帧确认 |
| 移动与朝向 | 邻近4个点共用20秒内移动记录；支持原地转向和手动到位后新画面识别；沿用旧罗盘俯仰重映射，避免旧路线朝向整体偏移 |
| 语音与字幕 | Android 中文 TTS：定位、出发、转向、到达、异常与障碍；字幕独立显示，支持关闭语音与重播 |
| 障碍提醒 | 沿用室内 Swin-L / Mask2Former 服务及策略版本2，普通目标2帧确认，近前方高置信行人即时提醒，3秒过期；不输出测距或自动绕行 |
| 生命周期 | 离开页面、切后台或切换连接时丢弃旧回调；导航请求不排队；独立障碍请求不等路线特征请求完成 |
| 原有宿主 | 保留 RoboGuide 导航归档、RealSense、NPU 与其他模块，NAVI 入口互斥判断不变 |

保留的 Flutter 对照源码不打包。旧版可选 Porcupine 唤醒词/GPT 对话助手没有移植进原生导航；本轮迁移保留的是导航语音播报与字幕，不能把两者视为相同功能。原生界面重新布局，不保证与旧 Flutter 页面像素一致。

## 目录与构建

- naviindoor/src/main：原生 UI、相机、传感器、TTS、HTTP、录制草稿与导航逻辑。
- naviindoor/src/test：导航规则、接口契约、障碍确认与草稿恢复回归测试。
- app/.../navindoor/NaviIndoorActivity.kt：继承原生入口，不再依赖 FlutterActivity。
- gradle/navi-indoor.gradle：检查 APK 和运行依赖，发现 Flutter 引擎、Dart libapp.so 或 Flutter assets 即失败。
- navi_indoor：历史对照，不在 settings.gradle 的构建模块中；prepare_navi_android.py 仅供旧版回溯，当前构建不调用。

JDK17、SDK36、NDK27.0.12077973、CMake3.22.1 与原宿主 LFS 资源准备好后：

~~~bash
./gradlew :naviindoor:testDebugUnitTest :naviindoor:lintDebug :app:testDebugUnitTest :navoutdoor:testSwinlDebugUnitTest :app:verifyNaviDebugApk -PswinlFast=true -ParchiveTest=true -PnaviIntegrationTest=true --no-daemon
~~~

## 后端与数据

使用现有 /encode/navigation、/encode/preprocessed、/obstacles/analyze、Supabase Auth/REST/Storage 接口。本次不迁移数据库、不部署新服务器、不改变网络入口，不新增网站源码。手机仍须能够访问配置的服务地址；换成原生不会消除网络中继的延迟。

旧完整路线无需重录，但必须有连续序号、有效768维特征和可用朝向。地图列表只查询 id/name，选中地图再加载图片，避免把全部 base64 地图随列表下载。原生版首次进入需要重新登录，旧 Flutter 登录令牌不迁移。

## 必须完成的真机验收

自动化与编译结果见[原生验证记录-20261120.json](原生验证记录-20261120.json)：321项测试通过，原生Lint为0个错误、54个警告；APK不含Flutter引擎和资源，签名与对齐校验通过。下列操作需要使用实际设备与现场路线验证，不能用构建成功代替：

1. 覆盖安装同签名测试包，核对两个服务地址，登录原账号并打开原地图。
2. 用已录制路线依次验证定位、出发方向、相似走廊推进、转弯、终点页面与语音；中途锁屏或切后台后恢复。
3. 对行人、椅子、门和楼梯测试提醒；检查长延迟时旧障碍会清除，不出现“安全通行”的错误承诺。
4. 录一条短测试路线，断开网络后继续采样，再恢复连接上传并核对点数；使用测试地图，避免覆盖正在使用的路线。
5. 检查照片选择、视频导入和中文 TTS；账号恢复链接需由服务实际发送邮件后验证。
