## FRI-001：Mission 运行期智能监督与策略建议

**动机。** 汇总每个 Mission 及其 Node/执行实例的真实状态，在停滞、能力不匹配或环境变化时，
更及时地识别问题并提出调整建议。提高有效完成率、缩短恢复时间是待验证假设。

**与已有能力的关系。** 仓库已有[受控运行期计划修订](runtime-plan-revision-v0.1.md)及
[运行期 MI 工作](runtime-mission-intelligence-v0.2.md)。已有实现保留原目标、有界授权、
独立 Review 和原停止/撤销门禁。这不等于已经实现持续智能监督；未来设计应先评估复用，
不能再建立一份调度、执行或资源权威。

**待评审的职责边界。**

- 监督输入来自 State/Runtime 等原权威提供的带身份、来源、时间、新鲜度与 unavailable 的视图。
  逻辑计划建议与实时 Node placement 分开，MI 不因此获得直接选 Node 或 ResourceId 的权力。
- 智能模块可以提出候选策略或计划修订；原 Review、Control Commit、Runtime fence、
  停止确认与资源释放仍分别生效，不能由模型直接下发任意设备指令。
- 本地避障、实时控制与最终即时安全仍由本地执行系统负责。模型判断停滞不证明机器人已停止。

**必须先回答的问题。**

1. 什么事实触发监督，如何区分正常等待、失联、慢服务和真实执行停滞？
2. 状态采样、异常检测、模型推理和策略切换各用什么频率？高频采样不必触发高频推理。
3. 如何去重、抑制反复改计划，并限制调用次数、切换次数、成本和原任务总预算？
4. 多 Mission、迟到回执、断线、模型超时和服务重启时，谁保留原执行与资源义务？
5. 如何用固定任务集比较完成率、恢复时间、误干预率、原任务稳定性和总成本？

提高调整频率不自动提高效率。应先比较事件触发、规则检测与模型推理的必要性，
再用独立实验验证收益和干扰；当前不承诺实现形态或算法。

## FRI-002：面向传统机器人的可选本地智能组件

**动机。** 传统机器人可能只有厂商 SDK、ROS action/service 或固定控制接口，
没有具身智能操作系统。未来可以研究部署在设备侧或附近计算节点上的可选组件，
将受支持的 canonical operation 转成可靠的本地执行步骤，降低接入成本。

**与已有能力的关系。** 现有 Node Service、Local Integration Engine 和
[设备接入规范](../extensions/device-extension-conformance-v0.2.md)已经负责注册、
固定 workflow、执行日志及状态/取消映射。新增智能能力不应取代这些机制，
也不要求所有机器人必须使用模型；现有本地 EAIOS 继续是受支持的接入方式。

**待评审的职责边界。**

- 全局 Mission 组织、节点选择与资源承诺仍由 RoboGuide 原层次负责。
  本地组件仅在已提交的 operation、参数、权限和预算内选择本地 How。
- 对象、目的地和操作效果保持原合同；自主路径、避障或有界重试必须符合已声明的本地能力。
  缺少搬运能力时不得用模型推理或接口存在来伪造可执行能力。
- 注册内容来自实际驱动、部署事实和 readiness 检查。组件必须支持明确的执行句柄、
  status、cancel、故障对账及无法确认时的 Unknown；不能把接收 ACK 映射成执行完成。
- 物理控制和最终即时安全须由实际控制器、安全机制及部署验收支持。
  新增软件或 LLM 不能自动获得这些保证。

**必须先回答的问题。** 首个真实设备与接口、可支持的 operation 集、规则/技能执行是否已足够、
智能规划的必要性、计算与断网约束、人工接管、命令生命周期、停止/恢复及设备级验收。
需要比较接入工作量、合同违反率、执行可靠性、延迟与成本，不能只展示一条成功演示。

## 维护与晋级规则

新增想法先记录 ID、动机、范围、待验证假设和不做事项。没有进入实施授权的条目保持 Deferred。
晋级时先写职责与生命周期设计；涉及架构语义或公开契约变化时，按仓库规则补 ADR，
再进入唯一实施队列。实验配置与原始结果按各自归档规则保存，不回填为此前已具备的能力。

[接入经验与验收清单](local-eaios-integration-lessons.md)记录已经遇到的工程问题。
修复一个当前接入缺陷，不自动批准实施本页的未来智能模块。
