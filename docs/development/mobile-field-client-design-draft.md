# RoboGuide 手机现场终端与交互节点设计草案

日期为 2026-11-04。本文供 RG 与 AGY 协作讨论和开发拆分，尚未冻结新增协议，
不表示人工对账解除或 Android Node 已实现。不在本轮改动现场部署或下发机器人任务。

## 定位与职责

手机是 RG 的现场交互设备，可以同时承载操作界面与可选 Node 运行模块。
操作员经手机查看和处理集群任务；需要接受 RG 调度的手机能力，才通过 Node 注册。
人、手机设备、Node 和本地服务分别保留身份。手机联网不能证明操作者正在现场。

| 角色 | 手机承担的工作 | RG / Robonix 保留的职责 |
| --- | --- | --- |
| 现场操作终端 | 查看状态、发起目标、请求取消、提交现场观察及处理意见 | RG 鉴权、任务与恢复决策、资源 Commit / release；Robonix 本机受理及执行 |
| 集群交互参与者 | 注册实际可用的采图、现场观察等能力，接收原 attempt，返回进度和产物 | RG 选择参与者和协调任务；手机本地模块处理权限、可用性、取消及执行结果 |

操作界面的每个按钮不注册为 Capability。只有需要 RG 独立选择执行者、承诺资源、
协调或恢复的完整任务，才形成正式操作与绑定。手机无需安装完整 Robonix，属于
[两类接入 ADR](../decisions/0231-local-eaios-and-device-integration.md)中的设备接入形态。
查看集群、操作任务的权限不能由 Node 注册自动获得，提供采图能力也不授予恢复管理权限。

```text
现场人员 → APK 操作界面 → RG Controller 操作入口
                                 ↓
                           任务、资源与恢复
                                 ↓
                         狗2 Node → Robonix → 狗2

APK 可选 Node 模块 ↔ RG 正式 Node Protocol
         ↓
手机相机 / 人员参与的现场观察模块
```

手机发出的机器人目标和取消请求沿 RG 正常路径进入 Robonix。本机动作、导航步骤、
即时安全与最终设备状态继续由 Robonix 负责。APK 不内置机器狗 SSH 或底盘控制链路。
手机的网络停止按钮表达任务取消请求，界面分别显示请求接纳、任务终止与设备停止证据。

## 第一阶段：现场操作终端

优先交付一个实际可安装、可联调的 APK。界面以设备、任务、待处理、记录四类页面组织。

| 页面 | 最小功能 |
| --- | --- |
| 设备 | 设备身份与名称、连接状态、数据时间；姿态、电量等按实际接通的数据源显示 |
| 任务 | 原 Mission / attempt、状态、进度和失败原因；指定设备目标经后端校验；原任务取消 |
| 待处理 | 等待处理的任务、为什么被保留、已有证据、需要现场核实的事项、处理意见提交 |
| 记录 | 谁在何时对哪个原任务进行了什么操作、服务端回执、证据附件、最终处理结果 |

设备名称旁显示可核对的稳定身份。任务同时展示 RG 与本机结果，允许出现
“本机已取消，RG 仍待对账”。连接中断或数据过期必须可见，缓存状态不作为当前状态。
没有新鲜的处理上下文时，界面可保存说明草稿，恢复后重新读取上下文再提交。
有副作用的请求不在断线后自动排队执行。响应丢失按原请求身份查询，不能换 ID 重发。

本阶段使用 Controller 操作接口，不要求手机先成为 Node。正式手机接入应配置受认证的
网络入口与角色权限，不能直接将当前 ThinkPad 的开发用 loopback HTTP 端口暴露给手机。
设备凭据可撤销，操作员身份可审计，APK 不携带共享管理员私钥或现场 SSH 密码。

## 当前人工处理问题如何进入手机

[狗2 P0–P3 实测](acceptance/2026-11-04-dog2-p0-p3-validation.md)发现原任务已取消，
但 Controller 因缺少安全声明与独立证据而保留任务槽。手机提供现场人员参与的入口，
该记录的正式对账解除语义仍需在 RG 后端实现。

建议的交互如下，具体命令格式待后端协议冻结。

1. 后端产生绑定原 Mission、execution、generation 和设备身份的待处理项，附原因、
   已有证据、缺失项和当前版本。APK 展示原始归属与可执行的处理动作。
2. 现场人员核对实机，提交观察事实、是否能判断、观察时间、说明及可选照片。
   设备拍照和人员陈述分别标记来源。远程看图与现场直接观察分别记录。
3. 后端验证人员权限、原待处理版本、证据新鲜度、请求幂等及当前任务状态。
   状态已经变化、上下文失效或证据不足时明确拒绝，返回最新上下文。
4. RG 按明确的恢复策略决定保持隔离、接受补充证据或完成当前人工对账。
   人工观察不能补写成原 deadline 内的自动停止证明，原失败和人工介入继续保留。
5. 需要再次执行时，另经正常任务准入。解除隔离不自动重放旧站立或导航目标。

待处理项不是一个“强制成功”按钮。观察事实、人的处置意见与 Controller 的资源释放
决定分别记录；Node 上报任务完成也不自动满足管理员权限。
普通现场确认不得被解释为任意安全策略的豁免。人工解除的适用范围、条件和证据规则
需要独立 ADR、版本与恢复验证，不能在 APK 中自行定义。

## 第二阶段：手机作为正式参与者

APK 加入可选 Node 运行模块，按现有 Node Protocol 实现注册、健康、能力就绪、
执行身份、进度、结果和取消。先评估现有 Node 运行代码的 Android 可复用范围，
再决定移植或兼容实现，不能仅显示在线标记就声称已完成 Node 接入。

首个能力建议为手机采图，其次是明确指定现场人员的观察任务。相机权限、用户是否
愿意接单、应用是否实际可接收任务，都影响能力就绪。手机和可执行能力的在线状态
分别呈现，后台受限或人员不在场时，不继续声明现场观察可用。

同一 attempt 持久化并重复查询，重复投递不重复弹出已完成任务或重复采集。
取消作用于原任务，应用重启后保留原结果或明确未决。采集照片作为真实 Artifact
记录来源、摘要、时间和原任务关联。人员身份和本机执行记录也分别保留。
室外定位、室内地图位置和人工选择的地点具有不同含义，不作隐式互换。

第一条协作用例可以是“狗2到指定地点并拍照，指定现场人员在手机上复核”。
机器人任务与人员复核各自具有真实结果、依赖和超时，RG 负责两者的协调。
手机 Node 掉线只改变自身可用性，不自动撤销机器狗已取得的任务或释放其资源。

## AGY 与 RG 的交付边界

| 工作 | 负责方与交付物 |
| --- | --- |
| APK | AGY 负责 Android 工程、页面、认证接入、请求与回执展示、现场观察表单、拍照及安装包 |
| 操作后端 | RG 负责可供手机访问的认证入口、原任务查询、任务命令、待处理项及幂等回执 |
| 人工对账语义 | RG 先设计和验证原身份、版本、权限、证据、资源处理及恢复规则，再提供冻结接口给 AGY |
| 手机 Node | 第二阶段共同实现协议兼容和本地能力，不把 Android 特有逻辑放进 Controller |
| 验收 | RG 提供真实测试部署与接口样例，AGY 提供 APK，双方联调重传、失联、过期和权限拒绝 |

当前源码已有下列接口，可用于第一阶段联调。实际部署是否启用对应鉴权及数据源必须核对。

| 已有接口 | 用途 |
| --- | --- |
| GET /v1/inventory | Node 可达性、报告健康、合同和资源 |
| GET /v1/resource-allocations | 当前资源占用 |
| GET /v1/missions/{id} | 已知 Mission 的状态，不是集群任务列表 |
| GET /v1/missions/{id}/execution-attempts | 当前原任务执行关联 |
| GET /v1/missions/{id}/recovery | 隔离、待处理和恢复视图 |
| GET /v1/executions/{id}/progress | 原执行进度 |
| GET /v1/executions/{id}/safety-stop | 原停止目的及证据状态 |
| POST /v1/missions/validate-plan | 固定计划校验 |
| POST /v1/missions | 提交符合现有协议的 MissionPlan |
| POST /v1/executions/{id}/cancel | 原执行取消请求 |

普通任务列表、可操作的人工待办聚合、现场观察提交和人工对账解除不能仅根据这些
查询接口声称已具备。现有 /review 针对 crash-loop review，不是本次 SafetyStop
人工解除入口；/attestation/evidence 是受约束的硬件证明流程，不是人员观察提交接口。
第一阶段先用真实已知任务展示，新增接口使用明确的模拟模式开发，待冻结后切换联调。

## 首版验收与本轮产出

首版依次验证连接并识别狗2、读取原任务、提出取消请求并区分回执阶段、展示真实待处理
原因，以及使用已实现后端提交一次归属正确的现场观察。旧 generation、越权、重复提交、
响应丢失、离线和服务端尚未实现的操作都应展示真实结果。

手机 Node 接入另做一项真实采图任务，验证注册、匹配、Commit、Bind、执行、Artifact
和取消/重启，之后再加入机器人与人员的协作任务。终端可访问与正式 Node 接入分别验收。

本轮仅形成设计草案和 AGY 分工，没有创建或通知 AGY 任务，没有安装 APK，未变更
Controller 人工恢复状态，也未向机器狗下发任务。
