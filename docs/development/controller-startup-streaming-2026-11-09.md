# Controller 启动与高频历史：分阶段优化

目标是让 Controller 的运行成本主要取决于当前对象、未结任务和必要恢复证据。
本轮第一阶段只优化恢复读取，不改变任务、租约、归档、权限或持久格式，也不清空历史。

## 第一阶段：单次流式恢复

原 Artifact Catalog 恢复把全部事件载入 Vec，反复解析同一 payload；定位恢复随后再次扫描。
对现场 801,957 条、1.44 GB JSON 的事件历史，这让普通遥测进入启动内存和 CPU 的关键路径。

State 的 `catalog_recovery_events` 在同一个 SQL mutex 下依次消费已归档的原始目录前缀和
未归档事件尾部。每条尾部记录只作一次 typed 解码，校验原 envelope/schema 和 adoption
来源，保留 Catalog 所需的事件，及时释放普通遥测。整个历史的时间上界仍被保留。
损坏的普通遥测仍然拒绝恢复，不通过过滤掩盖坏历史。

Artifact Catalog 同时收集原始定位证据；main 只消费一次该已校验结果，不再重新读取全表。
一般性的全事件读取 API 保持完整输出，受限 adoption 原始字节接口及归档合同保持原行为。

职责仍由 State 提供原记录及完整性验证，Artifact Catalog 构造其私有投影，main 完成启动
接线。没有新增存储权威、数据库代际、服务进程或动作执行路径。这是实现层性能优化。

复杂度：旧历史仍扫描 O(H) 字节；内存不再随无关遥测总量增长，而受相关 Catalog 记录、
原始 publication 校验记录、单条事件及已有有界归档前缀影响。它不是 O(1) 启动，也不能
把相关目录数据自身增长说成已消除。

## 第二阶段：正常重启只读有效投影与必要尾部

设计有明确来源与覆盖序号的 Catalog/定位持久投影，与原事务写入原子更新。启动校验
投影的完整性、权限来源、历史边界，再恢复必要增量；老数据库在显式迁移中建立覆盖依据。
索引必须从原日志可验证地构建，不以未知缺项的缓存替代权威。先审阅现有 Catalog archive
checkpoint 的复用边界，不增加另一套相互独立的权威。

目标：重复重启不再扫描累计遥测历史。验收须覆盖尾部追加、损坏、缺行、旧 writer、
事务回滚、恢复中断及原 Catalog/任务/Artifact 证据等价；不能只用空数据库测启动。
这部分尚未实现，需要单独的持久合同和迁移评审。

## 第三阶段：控制高频历史增长

| 数据 | 存储及恢复原则 |
| --- | --- |
| 当前 Node/State/Lease | 保留当前值与真实接收/源 epoch/sequence/TTL；恢复后重新核验实际会话 |
| Task、Commit/Bind、资源、取消/停止、Unknown | 保留完整当前恢复状态；重要历史可查询，原回执与防重复执行依据不能丢 |
| 周期遥测和重复结果 | 保留有限热窗口；不可变结果正文复用引用，长历史受控归档 |
| 决策实际使用的证据 | 按原 Task/attempt/来源冻结；不随普通遥测过期而被删除 |
| Control command journal | 按 checkpoint 与幂等/迟到命令覆盖合同归档，不能当普通日志直接删 |

payload 内容相同不代表测量时间相同：真实新测量、缓存重发、源重启必须分别处理。
本轮不更改 State TTL，也不降低心跳频率掩盖问题。既有归档机制的删除边界必须经过验证；
物理未知执行不能因压缩而变成完成、停止或自动重试。
这部分尚未实现。

## 验证方式

- State 测试证明丢弃无关遥测只影响内存输出，原记录不变、clock floor 保留；坏 JSON、
  错误 schema/envelope、缺失归档原证据仍失败。
- 原空间任务测试证明定位证据内容及顺序一致，启动消费后不再重新扫描。
- 使用同一份未删减的现场数据库副本、同一台 ThinkPad、原 mTLS/授权输入，分别启动旧版
  与候选 release，只监听 loopback，不连接真实 Node，不下发任何任务。
- 比较 readiness 时间、/proc 峰值 RSS，并核对 48 个 Mission、48 条 attempt、身份/授权、
  8 个 Artifact 和 verifier registry。记录机器、文件缓存及内存竞争限制，不将单次测量
  解释为跨硬件 SLO。
- 后续加入 1 万/10 万/100 万历史事件的规模测试；第二阶段必须证明相同有效状态下，
  正常启动不再随历史总量线性增长。

第一阶段验收测量由 `lab/rg-startup-streaming-20261109/` 保存。本轮不自动部署现场服务。

## 第一阶段当前结果

129 项 State 测试、318 项 Controller 测试通过；相关 all-targets Clippy（warnings denied）
与 rustfmt 通过。候选 release 通过真实私有 Controller/Node 的 17 项目标结算、缓存/离线
拒绝和重启恢复检查，保留原任务与依赖行为。

ThinkPad 的旧版副本对比尚未完成：最后取得的进度超过 136 秒，随后 SSH banner 超时。
已经尝试终止本次自有测试进程，但未取得终止确认。候选程序的现场性能对比未启动，
现场服务未切换。因此当前没有可信的新版本启动时间或峰值内存数据，也不能把通用进程
测试通过描述为现场性能验收通过。恢复 ThinkPad 访问后，先确认自有探针已退出及现场
服务健康；后续大历史对比应在有独立资源预算的环境执行。
