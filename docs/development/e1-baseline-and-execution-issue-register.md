## 责任与范围

- `E1-BASE-001` 的缺陷来自上游公开提交；我们负责发现、披露和验证本机选用版本，
  不能把发布回归的低分直接当成组织架构优势。修复不是重写 EMOS 的策略。
- `E1-EXEC-001` 属于 RoboGuide Local EAIOS 接入生命周期，不能归咎于官方任务、
  模型或物理机器人；Core/MI/官方成败规则不因此改变。
- 已证实的软件问题、离线测试通过、实际请求正确、物理执行正确和官方成功分别记录。
  一个层次通过不代表其他层次通过，相关现象也不自动成为全部失败的共同原因。
- 新问题若不阻止执行正确性或证据可信度，登记后进入后续版本；不无限追加当前论文范围。
  新版智能监督模块仍按 [未来研究想法](future-research-ideas.md)保持 Deferred。

## 本轮交付门禁

1. 两项修复分别测试，再跑组合路径和仓库质量检查。
2. 审查完的代码提交并冻结，真实小规模验收使用干净代码视图；禁止混用开发树。
3. 真实输入、工具输出、动作、原始失败和官方指标存独立原始目录，不直接提交/推送。
   经审阅脱敏的结果投影按
   [E1 结果发布政策](../../evaluation/docs/e1-results-publication-v0.1.md) 入库，
   原档备份、发布包和工程问题登记分别维护。
4. 验收报告明确哪些问题关闭、哪些仅离线通过、哪些仍未确定；生成新批量方案。
5. **扩展批量前核对用户授权与冻结协议。** 允许在明确授权下由验收门禁自动放行已冻结队列；
   不根据诊断样本的成功追加尝试或替换旧结果，普通官方 false 不构成追求成功的重试理由。
