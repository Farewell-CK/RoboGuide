# Runtime Reliability Fault Matrix

This matrix maps the first reliability-completion slice to deterministic offline evidence. The tests
inject faults at authority boundaries; they do not claim hardware, network-partition, or distributed
exactly-once certification.

| Fault | Required invariant | Executable evidence |
| --- | --- | --- |
| Controller crashes after intent commit but before Node receipt | Dispatch intent survives; restored nonterminal attempt is `Unknown`; no implicit action replay | `runtime::execution::tests::dispatch_outbox_survives_restore_and_receipt_is_idempotent`, `orchestration::integration_bridge::tests::durable_dispatch_crash_window_restores_as_one_recovery_event` |
| Node crashes around Local EAIOS dispatch | Journal distinguishes pre-dispatch failure from physical ambiguity and never authorizes blind restart | `node_service::journal::tests::ambiguous_dispatch_requires_reconciliation_and_never_restarts`, `node_service::service::tests::reconciliation_required_execution_fences_local_resources_after_restart` |
| Node route or lease is lost | Current attempt becomes `Unknown`; exactly one Runtime recovery transition is emitted; Group recovery stays Control-owned | `runtime::execution::tests::node_loss_emits_one_recovery_event_and_retains_attempt_history`, `integration_server::tests::unavailable_bound_actor_is_deferred_without_failing_server` |
| No replacement exists when recovery begins | Control retains `Blocked + unbound`; later Node evidence can resume the same need through Proposal, Commit, and Rebind | `control::tests::execution_ambiguity_recovery_resumes_after_candidate_registration` |
| Controller restarts after replacement Commit but before Rebind | The timer consumes the existing Control-owned commitment; it never creates a competing Proposal or reservation | `integration_server::tests::recovery_driver_rebinds_existing_commitment_first` |
| Duplicate or stale execution fact | Sequence reducer is idempotent and a wrong owner cannot poison the accepted sequence | `orchestration::integration_bridge::tests::execution_sequence_fences_stale_reconnect_events`, `orchestration::integration_bridge::tests::wrong_node_execution_fact_does_not_poison_sequence` |
| Cancel arrives before Execute | Node stores a tombstone and suppresses the later Local EAIOS invocation | `node_service::journal::tests::cancel_before_execute_is_durable_and_suppresses_dispatch` |
| Cancellation references an unknown execution | HTTP returns conflict, rolls back the batch, and leaves the durable writer usable | `integration_server::tests::unknown_execution_cancel_rolls_back_transaction` |
| Route loss or rejected receipt makes a relation endpoint ambiguous | The relation immediately becomes Unknown and fences progression without waiting for another Node fact | `runtime::relation::tests::physical_ambiguity_refreshes_relation_fences_without_another_fact` |
| Controller restarts while Mission cancellation is draining | `Cancelling` and per-attempt cancel intents survive; ownership is released only by explicit finalization after terminal evidence | `orchestration::tests::cancelling_mission_restores_and_waits_for_explicit_finalization`, `runtime::execution::tests::cancellation_intent_survives_restart_and_terminal_fact_clears_delivery` |
| Recovery rebinds a logical Role | Control requires a committed replacement; Runtime allocates a new attempt while retaining the old attempt and relation logical endpoint | `control::tests::recovery_pipeline_commits_then_rebinds_external_choice`, `runtime::relation::tests::relation_tracks_rebind_without_node_identity`, `runtime::relation::tests::shared_spatial_evidence_follows_rebind_attempt_identity` |
| Two Tasks use the same Role name and interleave recovery Commit/Rebind/Abort | Each exact Task/Role consumes only its own pending commitment; unaffected ownership remains stable, including zero-resource and restore states | `control::tests::ownership_model::ownership_model_fixed_seed_traces`, explicit extended `ownership_model_extended_traces` |
| Unsupported or incorrectly identified role recovery | Rejection occurs before Group lifecycle, reservations or event evidence mutate | `control::tests::ownership_model::execution_recovery_unknown_task_is_atomic`, `execution_recovery_identity_rejections_are_atomic`, `context_reuse_model_keeps_one_owner_until_context_release` |
| Malformed legacy binding or zero-resource pending checkpoint | Duplicate/overlapping Role coverage and wrong Task/previous-owner recovery commitments fail restore | `control::tests::ownership_model::legacy_checkpoint_rejects_duplicate_and_bound_unbound_role_overlap`, `checkpoint_recovery_requires_exact_unbound_slot_and_previous_owner` |
| Observation buffer fills or diagnostic I/O fails | Observation loss cannot alter durable fact/checkpoint traces | `integration_server::diagnostics::tests::diagnostic_sinks_do_not_change_durable_timer_trace` |
| Continuous exact-session ingress waits behind application work | Control can admit liveness without refreshing reported health or early ACK; ingress timestamps remain original | `control::tests::continuous_liveness::continuous_ingress_renews_control_without_refreshing_health`, `integration::grpc_server::tests::observation::custom_policy_and_original_ingress_survive_application_delay` |
| An injected typed Mission contract failure follows a private mutation | Candidate/events roll back; only A is held while B progresses. This tests the mechanism, not production error classification | `integration_server::tests::mission_isolation::local_failure_rolls_back_candidate_and_events_then_isolates_only_a` |
| A malformed or unsupported contract reaches real HTTP admission | Reject before execution with 400/409; retain existing memory/events/checkpoint and let other Missions dispatch without a fabricated hold | `integration_server::tests::mission_isolation::admission_contract_rejection_preserves_existing_missions_and_timer_dispatch` |
| Group stop facts arrive after a Mission hold | No replacement is prepared until explicit resume, including after durable restore; ownership/facts and the original deadline survive | `integration_server::tests::group_recovery::isolation::isolated_group_waits_for_explicit_resume_without_renewing_recovery_budget`, `restored_isolation_retains_group_stop_evidence_until_explicit_resume` |
| Peer readiness waits past its receive-relative TTL | Admission/replay cannot revive Ready; checkpoint is Fenced before the next timer, partial renewal remains Fenced, fresh acknowledgements from all peers restore Ready | `orchestration::integration_bridge::tests::relation_view::peer_readiness_is_owner_checked_expires_and_restores_fenced` |
| Control/shared/SQLite transition failure resembles a local error | Failure remains global and creates no misleading isolation | `integration_server::tests::mission_isolation::shared_or_unclassified_failure_is_not_quarantined`, `sqlite_failure_is_not_downgraded_to_isolation` |
| Terminal fact or cancellation arrives during Mission isolation | Raw terminal evidence and ownership survive; explicit resume consumes pending work without Execute replay; cancellation still waits for terminal proof | `integration_server::tests::mission_isolation::held_terminal_fact_is_retained_without_release_or_execute_replay`, `isolated_mission_cancel_retains_ownership_until_terminal_fact` |
| Operator resumes with stale generation/state or checkpoint write fails | Wrong generation/operation/lease rejects; HTTP separates rejection from persistence failure and never publishes the uncommitted candidate | `integration_server::tests::mission_isolation::explicit_resume_is_generation_bound_and_checkpoint_fenced`, `resume_rejects_expired_health_and_changed_operation`, `resume_http_rejection_and_sql_failure_preserve_durable_hold` |
| Concurrent outbox flushes redeliver one synthetic Execute before its receipt commits | Smoke accepts only an identical command retry and emits no new attempt/facts; changed command or ACK sequence rejects | `real_node_smoke::tests::exact_execute_retry_is_deduplicated_but_changed_command_is_rejected` |
| A Node sends an owner-mismatched or terminal-conflicting execution fact | The Runtime returns typed `FactRejected`; the application fences only that source session, while unclassified Runtime/Control/SQL failures remain fatal | `orchestration::integration_bridge::tests::execution_facts::wrong_node_execution_fact_does_not_poison_sequence`, `orchestration::integration_bridge::tests::execution_facts::terminal_execution_status_rejects_later_conflict`, `integration_server::tests::fact_batch::rejected_owner_fact_does_not_discard_another_sessions_accepted_fact` |
| Node command is accepted but lifecycle fact is delayed | Durable receipt closes the command-delivery ambiguity only; it does not synthesize Running or terminal state | `integration::grpc::tests::v0_4_round_trip_preserves_command_receipt_identity`, `node_service::service::tests::control_bound_command_round_trips_through_generic_engine`, `runtime::execution::tests::dispatch_outbox_survives_restore_and_receipt_is_idempotent` |
| Receipt/evidence carries stale session provenance | The application rejects it before changing Runtime delivery or relation state | `orchestration::integration_bridge::tests::command_receipt_requires_exact_admitted_session`, `integration_server::artifact_http::tests::spatial_map_cross_node_exchange_reaches_strong_verification` |

The cross-module Node Service test exercises formal Protocol v0.4 registration, application
acceptance, durable Execute receipt, generic Local Integration execution, and ordered Runtime facts.
The remaining rows deliberately test lower authority boundaries independently so failures can be
localized without real network or hardware timing.
