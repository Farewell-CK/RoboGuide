# Chat 真实使用反馈与原生任务 Agent

本轮基线是 `c17d07f9`，输入依据是用户提供的 AGY-CHAT-01 报告。报告记录了 ThinkPad
实际 Controller/MI 与 gpt-6.1-sol 的表现；原始证据在 Windows/ThinkPad 的归档目录。
本机根据报告复现软件行为，不把新增软件测试当成现场重新验收。

## 自然语言任务

默认 Agent 直接使用任务工具推进明确目标，不再向模型发布旧 `propose_action` 工具。
旧提议协议和手动命令仍兼容。

```text
让狗1去东区巡检，发现异常就记录下来。
先只规划，不执行。
把区域改成茶水间门口。
现在规划到哪一步了？
执行刚才显示的计划。
取消刚才的规划请求。
```

第一条在目标和成功条件明确后可创建正常执行 Request；若参数不明确，Agent 应自然追问。
第二条只创建 draft-only Request。修改、进度、审批和取消也有原生工具，不必翻译成命令。
已有审批策略、权限、完整显示版本和 Control 准入规则照常执行；不会因自然语言入口变强
而补造设备合同、绕过审批或把取消记录当成物理停止证明。

任务原文和澄清由宿主完整传给 MI。模型不能用自己的摘要替代约束。相同任务操作复用原
回执；一次任务操作出现未知结果后，Agent 可只读核对原命令，不重发或更换 ID。

巡检先展示当前节点合同。若狗1只有图像/主机检查，报告缺少导航/巡检或任务委派接入。
该问题需要实际部署本机技能及正确合同，不是 Chat 猜一个操作名便能修复。

## 本轮反馈修复

- 重复目录/工具调用返回已读结果并继续独立查询；零 I/O 的引用拒绝不占 HTTP 槽位。
  未完成的子问题仍明确保留，不能冒充整个复合问题已完成。
- “狗2”先由实际目录解析。两套上报保持歧义，但会显示有编号的对象选项，
  `/state #1 电量` 和 `object:lite3-dog2` 可明确选择原对象。
- `/raw` 随原身份、来源和显示确认保存完整历史原文与原读取时间；恢复时不发 GET。
  保存上限为 2 MiB；超限不存截断 JSON，也不把历史值当成当前状态。
- 实际 Responses 文本流可逐步显示；`stream-json` 增加 `assistant.delta`。
  未完成的流不进入工具执行或已显示历史，状态/任务回执仍由宿主最终核对。
- 终端保留紧凑处理轨迹，取消高频计时重绘和默认 CPR 查询。待发消息显示在输入区，
  可用 Alt-Up 取回编辑、Alt-Backspace 撤回末条，或 `/queue`、`/edit-queued 1`、`/dequeue 1`。
  正在处理的原请求继续收尾，撤回待发消息不会取消已经提交的任务。

## 复查修复：任务上下文与复合回答

对 `75790903` 的复查用隔离 MI HTTP/SQLite 和脚本化模型复现了四个缺口。修复保留自然
语言任务入口，并补充以下约束；没有改变服务端审批、任务合同或设备执行权限。

- 排队输入保存当时可见的 Request 和计划版本。自然语言执行、审批和修改不会改绑到
  随后创建的 Request；执行、审批也不能授权随后生成的新版本。普通节点刷新不改变计划，
  原版本仍可正常执行。失配时说明上下文已变化，请用户查看后重新明确操作。
- 原任务澄清期间，宿主按完整、带角色的用户原文保留“只规划、不执行”或“只讨论”的限制。
  补充区域不会取消限制；后续明确说“现在执行”可改变意图。助手的追问不授予执行权限，
  也不替用户设置限制。已创建 Request 的提交意图继续由服务端原合同管理。
- 任务回执与独立节点、任务、State 查询一起展示；State 仍在最终消费时重新检查有效期。
  任一部分失败会保留原因和 partial/failed 状态，不被成功卡片或模型措辞覆盖。
- 任务读取缓存加入实际解析目标和原命令身份/状态。同轮切换 Request 或执行后重新读取，
  不复用旧任务或旧阶段；目标和命令均未改变的重复调用仍复用本轮结果。

回归入口为 `mission/tests/test_workbench_task_context.py`，覆盖原四个失败复现、版本变化、
会话恢复、明确改变意图、混合查询失败和缓存刷新。全部是本地软件证据，不代表现场模型
选择工具的可靠性、真实机器人执行或 SSH 终端验收。

本次 20 项专项回归和合计 639 项 Workbench/提交意图测试通过；Ruff、严格 mypy 与函数
文档检查通过。新 wheel 安装后的实际 PTY 门禁通过，包含原生任务、SSE、队列及恢复；
门禁的合成 Controller 写入为零。原四个复现已先在修改前验证失败，再验证修复后通过。

## 配置和现场复验

新默认是 12 个 HTTP 槽位、8 次模型调用、120 秒原始期限。旧 profile 中明确的 4/3/60
不会被静默覆盖；现场复验可显式更新配置或运行：

```bash
roboguide chat --profile /path/to/workbench.toml --tool-limit 12 --call-limit 8 --turn-seconds 120
```

不支持流式的模型服务可用 `--no-stream`；不会在 HTTP 错误后自动重发请求。
入口统一使用 `roboguide chat`，系统 `rg` 继续表示 ripgrep。

viewer.crt 的 403 保留为现场授权配置问题，本轮不放宽认证，也不切换或部署现场身份。
真实机器人状态源、原生技能、真实模型选择工具的可靠性和 SSH/tmux 渲染仍需在更新客户端后
分别复验；现场 Controller 和 MI 进程没有在本轮重启。
