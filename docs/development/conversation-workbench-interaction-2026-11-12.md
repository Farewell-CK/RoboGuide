# Chat 日常对话与终端交互修正 · 2026-11-12

本轮由实际安装后的对话失败触发：`你好` 被送入要求当前证据引用的模型解释流程；
查询运行任务时，完整历史目标挤占证据预算，模型又继续查询已结束的旧 Mission；
终端处理期间拒绝下一条输入。以前的软件协议和权限回归没有覆盖这些日常体验，
不能用以前的测试数量代替本轮的实际交互验证。

## 行为

- `你好`、`你是谁`、功能介绍由工作台直接回答。常见的节点数量/能力、当前运行任务问题
  各执行一次当前 Controller 查询，不需要模型往返；复合问题和其它表达继续使用模型。
  本地匹配只接受完整问题，不吞掉 `你好，查节点` 中的实际查询。
- 新增 `/missions active` 和闭合只读意图 `active_missions`。按当前身份可见的原始 State
  生命周期统计 Running、Accepted、Cancelling、Completed、Failed、Cancelled 和 Unknown。
  Running、Accepted 与 Cancelling 分别显示；列表只列活动或未知项。
  Cancelled/Completed 的 Task 仍显示 Active，不会使其 Mission 被当成运行中。
- 生命周期只使用原始 `roboguide` / `derived` / `roboguide:runtime-orchestration` 来源。
  缺失、冲突、过期或无效来源保留 Unknown；无关遥测不覆盖原运行状态。
  目标描述与运行状态独立，缺目标不会把已知 Completed 改成 Unknown。
- 全部响应参与统计，展示行和长目标有明确上限。展示截断与来源完整性分开记录；
  大证据保留有界首尾摘要和子读取可用性。模型解释失败时仍保留已经读取的事实。
- 终端使用保留滚动历史的带边框输入区，显示模型、Controller、身份、会话、当前阶段、
  等待时间和队列。Enter 发送，Alt-Enter 换行，`/` 补全命令；中文按终端列宽换行，
  不因显示宽度丢掉回复尾部。不支持 CPR 的终端也能在输入区看到处理状态。
- 普通问题最多排队三条，并串行处理一次。入队时冻结已经展示的对象引用和有界历史，
  查询仍读取当前证据。明确依赖显示序号的忙时输入保留为草稿，要求完成当前回复后重发。
  执行、确认、取消、会话切换及依赖当前计划的命令不会排队或自动授权。
- Ctrl-C 清除本地输入/等待队列、停止本地显示，原请求继续收尾；实际取消仍用 `/cancel`。
  `/quit` 等待已发请求收尾，实际显示、持久化和确认采用原有 DisplayTurn 边界。
  `--plain`、管道和 `--ask` 保留普通文本入口。

本轮没有改变 Controller、Mission、Node、恢复、存储或物理执行权限与协议。
