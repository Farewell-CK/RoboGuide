## 计划与进度

任务卡片先显示中文阶段、提交方式、目标和步骤概览。新计划与修改版本继续显示完整
原始计划，参数按层级排版，包含任务、角色、Context 与全部其他字段。特殊不可见格式
字符使用 JSON 转义显示；没有用模型摘要代替参数。

同一个已完整展示并确认显示成功的 Request/版本/摘要/完整计划，后续进度读取使用简洁
卡片。状态、约束、问题和审批原因仍展示，避免每次追问都重复完整参数。切换 Request
不再误报“版本 1 → 1”；版本修改、显示失败与恢复会话后必须重新完整展示。

用户可直接说“展开当前计划的完整参数”，由本地 `show_plan` 工具展开已取得的版本，
也保留 `/plan-detail`。展开不查询当前执行状态，不发送任务操作；执行与审批仍核对
原始完整显示和服务器当前版本。

## 等待与待发消息

- 长等待在 15 秒、45 秒给出阶段和真实耗时，保持原始请求继续处理；没有每秒重绘。
- 忙碌时 `/help`、`/status` 即时显示本地说明或前台状态，不排队、不占新的查询/模型调用。
- `/queue` 多行内容按实际换行显示；开始处理待发消息时显示对应问题预览。
- 输入区预览按终端字符宽度截短，中文窄屏不再按 100 个字符硬撑；完整原文保持不变。
- 回复标题明确标为“部分结果”或“本轮回复未完成”，不把读取失败解释成设备或任务失败。

启动说明同时给出查询和自然语言任务示例。Ctrl-C、任务取消、队列撤回与会话切换的
原有语义不变。上游没有文本增量时，阶段与等待提示也不会伪装成流式文本。
