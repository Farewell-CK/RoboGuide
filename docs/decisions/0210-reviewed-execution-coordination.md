# ADR-0210: Reviewed complete-cohort execution coordination

Status: Accepted and implemented; local software-process acceptance passed on 2026-10-25.
See [the acceptance](../development/acceptance/2026-10-25-execution-coordination.md).

Control retains resource and Group ownership; Runtime retains attempts; Local EAIOS owns
Immediate How and final safety. Running preemption and coupled recovery must not weaken the
existing independent-Role continuation gate. They instead use a fresh reviewed semantic plan
and fresh Group through the existing complete original stop/revoke/revision transaction.

Runtime revision v0.6 adds an explicit candidate coordination declaration before output,
provider claim or Review. It freezes the source revision, complete current attempt set,
membership, actual operation-owned recovery/safety support and original caller. Review binds
its digest alongside original Memory declarations. Running preemption additionally freezes a
same-tenant higher-priority Ready beneficiary and actual shared exclusive-resource conflict;
current priority, source identity and eligibility are rechecked before stopping and switching.
The same authority transaction must admit an actual new beneficiary Runtime intent through normal
Control on an originally conflicting resource before source redispatch. Otherwise the complete
switch transaction rolls back and original stopped ownership remains. The original switch budget
and exact beneficiary admission/resource history survive recovery; aging cannot let the resumed
victim acquire the released resources before this admitted beneficiary.
The declaration does not create a Node, reserve capacity or prove a stop. Original candidate,
policy and switch budgets apply without renewal. A source change requires a new bounded ticket.

Coupled recovery replaces the complete cohort, with no independent Role Rebind shortcut.
The reviewed successor uses deployment-defined canonical operations and preserves original
satisfied Tasks, Context safety, original goal, original acceptance and all prior attempts.
Handoff and regrasp require original source Memory/context transfer and operation-owned device
observation assurance. A software-process exit cannot satisfy that requirement. Local EAIOS
supplies safe holding/release behavior and the target operation; Core never generates motion,
reset, grasp or vendor commands. Independent original-goal verification remains mandatory.

Decision-policy registry v0.3 may explicitly monitor a Readiness gate during execution. Each
actual attempt freezes its original active gates. Missing, conflicting, stale or revoked
required evidence invokes the existing complete Group stop/hold and Memory revoke. Deleting
or changing a rule cannot silently authorize an already running attempt. Current decision
evidence and original gate identity remain inspectable; neither metrics nor a caller Boolean
is a safety certificate. Readiness/outbox rechecks precede every delivery.

Controller wrapper v59 and recovery v0.28 fence these new authorities. Original v58 topology,
v57 scoped maps and all preceding source/SQL/CAS contracts retain their exact meaning. Recovery
retains immutable coordination and active-hazard histories, validates their original joins and
does not renew clocks, start services or infer physical continuity. Node and canonical MissionPlan
contracts are unchanged: registered operations and existing safe-state/Memory protocols carry
local semantics. Actual software-process and independent file verifiers validate the software
paths; device/handoff/regrasp observations remain unavailable without actual hardware evidence.
