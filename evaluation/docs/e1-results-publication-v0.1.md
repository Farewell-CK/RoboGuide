# E1 结果发布与维护设计 v0.1

状态：设计规范 v0.1；首版 [离线工具](e1-publication-tools.md) 已实现 staged 原档导入、
四类历史清点和发布包复算。下文的目标设计与已支持源格式仍须区分；其他历史格式
迁移和独立原档备份不因此完成。工具不启动模型、仿真或批量。

维护入口：[E1 结果台账](../reports/e1/README.md)。

## 1. 目标与责任

为每项已发布统计建立从报告、逐次运行到原始证据的可复核链路。代码仓库保存经过
审阅、脱敏的轻量发布包；原始运行目录在独立归档存储中保存。仅有本机路径的材料
必须标记为尚未备份，不能宣称远端证据齐全。

发布层属于 Eval Harness 的离线报告维护，不参与运行、准入或判定。它复用
[Population Manifest、Run Pairing Evidence、Pair Manifest](e1-fairness-foundation.md)，
原样引用 [B1 admission 与官方结果](evaluation-evidence-validity.md)，不重定义
Formal population、Pair Validator、Mission completion 或 Habitat 成功条件。

报告记录已观测事实、分析与待验证假设。论文复现的配置差异、额外 Local How、原生
源码兼容修复和证据缺口均须披露，不能因两个系统的模型名称相同就声称严格等价。
数据 hash 用于核对内容，不代替原始来源、受信采集或独立备份。

## 2. 入库边界与现有材料

| 材料 | 保存位置与规则 |
| --- | --- |
| 结果总索引、逐 workload/运行记录、统计、分析报告 | 审阅脱敏后发布到 `evaluation/reports/e1/` |
| 冻结配置、样本选择、代码/Prompt/二进制/数据集身份 | 保存必要的可移植投影或既有源文件引用，不复制凭据和机器配置 |
| 原始请求响应、视频、完整轨迹、事件、数据库、原始 Manifest | 保留独立原始归档；仓库仅保存已核验的索引和内容摘要 |
| 运行时 `results/`、`evaluation/results/`、本机 `local.yaml` 和环境文件 | 继续 Git 忽略；不得直接整体加入版本库 |
| 通用问题、接入经验、延期研究想法 | 维护现有文档；发布包引用稳定问题 ID，不复制另一套问题台账 |

早期 `evaluation/baselines/`、`evaluation/e1/` 内已跟踪快照保留原意和原路径。
新发布不移动、不删除、不回写这些历史材料，也不批量扫描后直接上传原日志。
其历史存在不表示满足本设计；导入时需单独列出来源和缺口。
发布文件默认不超过 1 MiB，超限须说明并审阅；原始大文件继续走独立存储。
必要时按有稳定索引的分片发布，不能截断记录或删除失败来满足大小限制。

本政策取代活跃维护文档中“所有真实实验结果均不得入库”的笼统说法，允许提交经
审阅的发布包。原始工作输出仍不入库。本政策不是自动上传、创建远端存储或开始
实验的授权；每次操作遵循用户实际批准的范围。

## 3. 目录与发布版本

以下是目标布局；未有首个真实发布时不创建空批次、空清单或伪造示例成绩。

```text
evaluation/reports/e1/
├── README.md                         # 维护入口、使用边界、导入状态
├── index.json                        # 有真实发布后生成的批次/修订索引
└── cohorts/
    └── <cohort-id>/
        └── revisions/
            └── r0001/
                ├── manifest.json     # 发布身份、来源、方法和配置引用
                ├── workloads.csv     # 计划清单及执行覆盖
                ├── runs.jsonl        # 每个实际运行的原始事实投影
                ├── pairs.jsonl       # 精确两臂引用、可比性及限制
                ├── summary.json      # 程序生成的分母、统计和缺口
                ├── REPORT.md         # 人可读的分析和使用限制
                ├── artifacts.json    # 原始/脱敏材料索引与备份状态
                ├── changes.json      # 首次发布或修订的原因和差异
                └── SHA256SUMS        # 本修订文件的原始字节摘要，不包含自身
```

`cohort-id` 标识既定实验集合，不使用“最新成功”之类的结果性名称。同一运行条件与
原始清单的统计修订新增 `r0002`，不覆盖 `r0001`；新的运行代码、模型、配置、目标清单
或实际重跑产生新 cohort。补跑引用原计划和原认领记录，不能冒充原批次已完成。

`index.json` 仅维护批次身份、类别、用途、当前审阅修订的路径与摘要，以及被替代或
撤回的发布说明。它不复制成绩作为第二个手工事实源，不按成功率选择“推荐版本”。
每个修订记录实际生成/审阅时间、维护者、导出器代码 SHA 与依赖、源文件摘要。
运行代码身份与报告生成代码身份分开；不能把发布当天的 main 填成旧运行代码。

## 4. 批次和样本选择

`manifest.json` 至少包含下列投影组。正式 JSON Schema 在工具实施时单独版本化；
本设计不宣称现有 runner 已生产这些新发布字段。

| 组 | 必需内容 |
| --- | --- |
| 发布身份 | 发布格式版本、cohort ID、修订号、生成者/时间、导出器身份、源证据集合摘要 |
| 原始出处 | 原 cohort/batch/Population ID 和 digest、原始 run 命名空间、来源文件引用 |
| 用途 | `primary`、`diagnostic` 或 `retry`；历史导入是来源属性，不把导入日期当运行日期 |
| 选择方法 | 原始完整 selector、纳入/排除理由、选择时间；预注册证据引用或明确 `retrospective` |
| 工作负载 | family、dataset revision/digest、config/task-spec/goal/指令身份、scene、episode、seed |
| 实际实现 | 各臂完整代码 SHA/已观测模块或 binary 摘要、Prompt/Local How/兼容修复与开关 |
| 模型与预算 | 分 MI/原生 Stage1/Stage2 的请求模型、实际返回身份、API 类别、参数/恢复/超时和原始步数 |
| 状态与限制 | 计划覆盖、原批次终态、未决缺口、可支持的研究结论及禁止外推的范围 |

一个历史集合若混有多个已知代码或配置版本，按实际条件拆为子 cohort 并保留父索引。
无法拆分的记录标记为历史混合集合，只作历史覆盖说明，不能生成同一版本性能。
缺少原始配置、运行身份或冻结请求的字段保留 unavailable 和原因，不从当前代码推测。

四类 E1 清单分别维护：导航、感知、单层搬运、多机器人重排。历史四类 478 个
workload 的索引是历史任务覆盖范围，不是 478 个同版本、严格配对、均有官方结果的
实验声明。额外变体独立登记；逐轮迭代、重试和诊断不增加独立 workload 数。

## 5. 三种身份与去重

### 工作负载引用

优先引用实际 `population_manifest_digest + pair_id` 和完整 workload 字段。
跨批次匹配须核对 family、数据集、任务配置、episode、scene、seed、指令和 goal
身份；单独 `Episode51` 或同名 `pair-0001` 不是全局标识。历史字段不足时标记
`identity_unresolved`，不能仅凭文件名判为相同或严格可比。

### 实际运行身份

`runs.jsonl` 一行代表一次真实执行，使用原始来源命名空间、原始 run ID 和 arm
组成限定身份。原始 runner 可能在每个目录重复使用同样的 run ID，不能当作全局唯一。
来源命名空间随原档首次导入固定，复制、备份或迁移路径不会创造新执行。

原始身份未完整归档时，保存稳定导入引用并标记其不确定性，不能生成“独立执行已证实”
的结论。无法确认两份材料是复制还是独立运行时，禁止将其当作两个独立样本计数。

### 配对和复用引用

`pairs.jsonl` 只引用两个精确的实际 run；保存原 Pair Manifest、实际 reset 比较和
比较政策身份。若某批复用历史 EMOS arm，引用相同原始运行并标记 `reused`，原运行
时间保持不变。各 cohort 可引用它，但跨 cohort 总览须按实际运行身份去重，不能
把复用次数计为新鲜模型/物理执行次数或独立重复实验。

`retry_of` 指向原实际运行，`diagnostic_of` 指向被调查的运行或问题 ID。
重试/诊断的成功不能替换 primary 结果；同一 workload 最好一次的成绩不作主成绩。

## 6. 运行事实、官方结果与未知状态

每条运行投影保留原始值、源文件/字段定位和摘要，至少包含：

- 原始执行/物理 episode 是否发生、进程结束、Mission/Task/技能结果和各自证据；
- 官方 `pddl_success` 的严格 true、false 或 unavailable，以及原始 authority 来源；
- provenance、Formal/benchmark admission 及其政策版本/原始 verdict 引用；
- 原始失败 owner、失败阶段、模型/Provider incident、证据采集缺失和诊断损失；
- 原始参数、调用数、usage、耗时及采集范围；缺字段不填零；
- 实际 reset 与加载模块身份、baseline/Local How 差异及观测限制。

原生 EMOS 没有 RoboGuide admission 的记录保留 not-applicable；不能补写通过。
额外离线复核保存在独立 assessment，记录实际评估器版本、输入与时间，不改写
原始 verdict。旧 scalar-only reset 不能补标成完整姿态匹配；Pair Validator 的通过
也不自动证明“只改变组织层”的因果比较，须披露本地策略差异。

`workloads.csv` 覆盖全部计划条目，保留各期望 arm 的执行状态引用：未开始、进行中、
已结束或执行状态 unknown。明确未开始需要原监督记录；材料缺失不等于未执行。
MI 提前失败可属于已结束运行且 `physical_episode_executed=false`，不是“未运行”。
单臂诊断只声明实际计划的那一臂，不能为另一臂伪造 false 或 unavailable 执行。

## 7. 统计口径

所有统计由导出器从固定修订记录重算，报告不手工编辑数字。至少发布：

1. 清单覆盖：计划 workload/arm、各执行状态、已取得官方结果和身份未解条目。
2. 原始逐臂结果：true、false、unavailable；不把 unavailable 或未执行填为 false。
3. 原有政策决定的 Formal 和 benchmark 分母、各自 true/false/unavailable 计数，
   不因 MI、Control 或 Node 失败就从 Formal 分母排除。
4. 双方官方值均可用且符合既定比较条件的 pairs：双方成功、仅 RG 成功、仅 EMOS
   成功、双方失败；不可比、缺失和 unavailable pairs 单列。
5. 实际新鲜运行与复用数量、primary/retry/diagnostic、不同版本和额外变体分别统计。

若展示比例，必须携带 numerator、denominator、分母定义和选择方法。零分母的
比率为 unavailable，不显示 0%。`S/(S+F)` 只能明确标注为“官方真值可用子集”，
不能作为包含早期系统失败的整个实验集合成功率。计划未完成时先报告覆盖；同一
历史集合的选定版本总览不生成混合版本 E1 总成功率。

统计导出严格消费已有 admission，不能借发布规则调整 Formal population。
诊断样本即使全部成功，也不能据此声称总体提升；同名 workload 的历史前后变化
若未重新证明初态和所有 held-constant 条件，只能描述变化，不能断言单项因果。

## 8. 原始证据备份与脱敏

`artifacts.json` 为每项引用保存稳定 artifact ID、来源角色、逻辑路径、原始字节
SHA256、字节数和可访问性。具体机器的绝对路径只保留在本机导入映射；公开索引
使用可移植引用，缺远端位置时保留 null。未知 hash/size 明确 unavailable。

备份状态分为 `local_only`、`backup_unverified`、`backup_verified`、`unavailable`。
只有从独立备份读取并核对实际长度/摘要之后，才能记录核验时间和 `backup_verified`。
同一磁盘再复制一份不是独立备份；同目录生成 SHA256SUMS 也不是备份成功证据。

存储服务和容量待选定，不在设计提交中创建付费资源或声称已有完整备份。
仓库不能只保存无法从其他机器使用的绝对路径，却宣称结果已可复现。
独立备份的访问控制与仓库可见性分别核对；未获准公开的第三方数据不打包上传。

脱敏导出采用字段白名单，不原样复制 `environment_overrides`、argv、HTTP headers
或环境文件。不得发布凭据内容、前后缀、hash、Authorization、带 token 的 URL 或
其他敏感环境值。Provider 的逻辑身份、API 类型和非敏感参数可用于配置比较。
需要稳定访问的归档 URL 不嵌入临时签名或密码，认证通过仓库外的授权方式完成。

对原始档案的脱敏副本另外记录 export digest、变换版本、脱敏原因和原 artifact
引用；不能将脱敏后的摘要冒充原始字节摘要。原始证据不因脱敏被覆盖。
发布包扫描器必须检查内容和元数据；不能只检查文件名或 `.gitignore`。

## 9. 发布、修订和撤回流程

```text
原始执行结束并保存证据
  → 检查实际关闭/采集状态，列出缺口
  → 只读导出到全新 staging 目录
  → 自动校验和独立重算
  → 脱敏与人工审阅
  → 提交完整修订并更新总索引
```

原始 Manifest、verdict 和报告不被导出器写入。导出不允许 Provider、Simulator、
Mission Request 或 runner 启动；缺证据就给出缺口，不为补齐报告自动重跑实验。

修订记录 `supersedes_revision`、原因、受影响记录/统计、原证据引用和新评估器身份。
只是统计错误时不生成新执行。发现不可使用的已发布结论时，索引立即标记撤回原因，
保留旧修订及原结果。新证据允许更新 assessment；不能凭空把历史失败改成成功。
分数变化不能成为删除发布的理由。

`staging`、`reviewed`、`frozen`、`withdrawn` 描述发布状态，不代表任务成功或证据
完整。Frozen 发布也可有明确的历史 unknown 和部分覆盖；报告必须写清限制。
`index.json` 最后更新，只引用齐全修订；中断不产生“已完成”索引或覆盖旧发布。
SHA256SUMS 包含本修订文件而不含自身，文件摘要与语义规范化 digest 分开命名。

## 10. 离线工具和验收要求

`evaluation` 内的首版离线导出/校验不新增实验调度器或第二套准入政策。
支持范围与命令见工具文档；本节是持续验收要求，不意味着每个历史源格式已支持：

| 检查 | 拒绝或保留的条件 |
| --- | --- |
| 身份与引用 | 重复/冲突 run、未限定 pair ID、未知来源、非法摘要、悬空引用；缺证据不能生成可比结论 |
| 覆盖与选择 | 漏计划条目、诊断混入主批次、回溯选择伪称预注册、未执行被填成失败 |
| 重试和复用 | 相同原 EMOS 运行被重复计为新执行、重试覆盖 primary、不同版本被合为同一性能 |
| 结果权威 | Mission Completed 填作官方 true、false/缺失混淆、缺 admission 被补通过 |
| 统计一致 | 汇总与逐条计数不符、分母不闭合、零分母填零、同一 slot 冲突引用 |
| 证据与脱敏 | 字节/大小不符、敏感字段、路径逃逸、意外符号链接、伪称远端备份完成 |
| 故障与可复算 | 导出中断保留 staging、不发布部分索引；同版本同输入输出稳定；原始目录字节不变 |

CI 校验已提交发布包的格式、引用和重算结果，离线运行，不需要凭据、原生 EMOS、
Habitat 或 GPU。可离线校验的发布字段与需要外部归档才可核验的事实明确分开；CI
不能把没有访问原档的通过结果包装为完整原始证据验证。
真实备份核验和人工语义审阅分别保存收据。公开 run/artifact 形状、引用和重算检查
已实现；独立原档备份仍未建立，不能列为已通过门禁。

## 11. 首次迁移与维护安排

1. 建立四类历史清单与来源目录，不因只找到一部分档案就宣称其他实验未发生。
   历史混合代码拆分登记，附加变体和研究诊断独立索引。
2. 导入最近感知/重排 primary 及已留存重试，各自保留原始版本、未运行和复用情况。
3. 导入本轮固定小样本诊断，保留其失败选择/成功控制及实际单臂/配对结构。
4. 核验原始位置、内容摘要、脱敏投影和独立备份状态；先形成候选发布包。
5. 审阅并发布阶段快照；E1 最终结束仍遵循 [收尾计划](e1-closure-plan.md)，不以发布
   成功或某个分数代替完整实验验收。新批量仍需单独授权。

每批结束时更新索引和该批发布修订；通用问题引用
[E1 问题登记](../../docs/development/e1-baseline-and-execution-issue-register.md)，
接入经验引用 [Local EAIOS 经验](../../docs/development/local-eaios-integration-lessons.md)。
导出器实现、历史迁移、原始备份和最终论文结论分别验收，避免将文档存在当作已完成。
