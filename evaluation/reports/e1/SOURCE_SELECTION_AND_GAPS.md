本次只读清点和发布，不调用模型、仿真或硬件。原始成绩、目标和 admission 保持原意。

## 为什么选择这一批

首次迁移选择原 ID `roboguide-e1-staged-batch-20261027T015410Z-1ixj2e2l`，
原因是它同时保留完整冻结 selector、213 项 CASES、RUN_MANIFEST、最终 paused STATUS、
原生复用选择、逐次结果、Pair Manifest、原始 admission 和调用记账。不是依据成功率
选择。包内有全部计划条目；原档技术暂停、三项未派发、全部失败和独立重试均保留。

其他来源的处理依据：

| --- | --- | --- |
| 历史导航 | 99 workload 的逐臂原报告和运行目录 | 四类清点；缺完整 Pair Validator 资格，未补造可比结论 |
| 历史单层搬运 | 166 项原记录，含保留/续跑及多个版本 | 四类清点；原记录与独立复核分开，不按当前代码回填 |

| 最近 staged 主批 | 明确完整计划、原始失败和闭合记账 | 首次完整迁移对象 |
| 小规模物理/模型诊断 | 独立 Manifest 和固定样本 | 保留独立来源；不代替主批次性能 |

来源位置通过 `artifacts` 的命名空间、逻辑路径、原始字节摘要和大小引用。机器绝对
路径只保留本机 witness；public artifact `remote_uri=null`，没有假定已建立云备份。
“已定位运行记录”与“物理 episode 已执行”分别统计：清点 `summary.json` 的
`groups.*.arms.*.physical_execution_observed/physical_execution_unknown`，以及迁移包的
`families.*.groups.*.*.physical_episode_executed/physical_episode_unknown` 给出可复算
计数。官方 unavailable 不等同于没执行；没有物理证据的记录也不会自动标为已执行。
各旧版本完整 SHA 与原始模型声明分别保留在清点的 `original_code_identities` 和
`model_declarations` 中，不把表中的历史混合集合当作同一版本成绩。

## 仍存在的证据缺口

1. **原始备份**：本包能够独立重算投影统计；全部原档仍 local_only。独立存储位置和
   恢复/校验收据尚缺；视频、数据库和逐步轨迹未在本阶段逐字节穷尽验证。
2. **覆盖**：staged 感知有一次任务启动前 OSError 和三项没有派发的清单条目；原档
   没记录该 OSError 的 errno/确切端口。不能把它们当作官方 false 或偷偷补跑。
3. **历史完整性**：旧感知清单中未定位的 55 项不能由新版本覆盖补写成旧运行。
   原始 locator 只是查找入口，本阶段重新读取了能访问的原始 JSON。
4. **物理配对**：旧 reset 只记录位置与角度标量。相同 seed、原记录 matched 和 Pair
   Validator 通过均不足以补证完整方向或严格等价的所有条件。
5. **实现身份**：EMOS 行中的原 launch SHA 表示启动器/封装版本，不自动证明原生
   仓库的 Git 身份；部分旧代码身份不可用。不能用当前 main、文件名或模型名补猜。
6. **基线配置**：这批早于显式 HSSD 目标身份兼容修复；模型也不同于论文配置，
   且 RG Local How/Guard/反馈与原生有已披露差异。不能把本机低基线分数直接当作
   组织架构优势，也不能称原论文精确复现。对应既有问题 `E1-BASE-001/002`；
   不在发布层重开同一缺陷。
7. **失败归因**：能确认的 owner/stage/code 按原值保留，缺少阶段的记录明确 unknown。
   抓取、复位和检测等具体根因仍需原始轨迹支持，不能由失败标签直接推出。
8. **历史独立复核**：单层搬运的两条原生原结构化 unavailable 曾被独立终态材料复核
   为 true；本清点保持原始值，并在逐行 assessment 字段保存既有复核声明。此处未
   重新解析全部二进制终态证据，不能把它们悄悄替换成 primary 结果。
9. **历史配对口径**：单层搬运逐对原始 `comparison_eligible` 为 160 对 true，旧
   FINAL_BATCH_SUMMARY 的汇总写 159。清点显示逐对原标志，不把它升级成严格有效配对；
   差异原因未在本阶段定位，旧汇总和原记录均不改写。导航的对应资格缺失则保留 unknown。
10. **时间与成本**：原进程只留下 wall time，缺完整开始/结束时刻；Provider 首末
    调用时间另存，不能代替物理执行或进程关闭时间。token 为归档 usage，尚无统一
    价格/账单证据，不能转成实际支付金额，也不能仅比较 token 总数推断组织效率。

物理初态限制沿用 `E1-EVID-001`；本地完成与世界真值分离沿用 `E1-LOCAL-001`。
后续导航、抓取、复位、通信和上下文成本问题仍由原
[问题登记](../../../docs/development/e1-baseline-and-execution-issue-register.md) 维护，
本结果包不将离线软件修复或统计重算当作这些问题的物理关闭证据。

## 论文可以说什么

- 可以报告：在明确的冻结条件与计划覆盖内，RG/EMOS 的官方三态结果、原记录配对
  子集、调用/耗时及失败分布。正文须注明 unavailable、未完成条目、复用和版本。
- 可以报告：可复算的实验工程发现及其证据层次；初次物理失败与后续接入缺陷分别论证。
- 不能报告：统一版本四类总成功率、只改变组织层的因果收益、当前 main 的成绩、
  论文原表精确复现，或“所有 E1 已完整结束”。
- 后续需要：独立原档备份、补齐可访问证据、审阅新的冻结基线条件；新实验方案另行
  预注册与授权。一次任务成功或新统计入库都不构成批量自动启动条件。

## 待补工作的顺序

1. 先审阅当前阶段包和原生基线兼容性披露，确认论文采用完整系统比较的范围。
2. 对导航、单层搬运分别迁移可访问的原始清单、混合版本与独立 assessment，
   追索旧感知 55 项和历史 160/159 配对差异；找不到的材料继续保留缺口。
3. 经独立存储授权后备份原始材料并实际恢复核验，逐类补充未穷尽检查的大文件。
4. 后续真实对照另行冻结代码、模型、预算和全部清单，保存两臂 reset 后的完整姿态、
   已加载的原生/接入模块身份和失败关闭证据。旧四个缺口及失败选择复测须有新 cohort
   引用，不替换本包成绩。此项是待审阅实验需求，本轮没有执行。
